# Code Review General

在 Claude Code 原生 `/code-review` 之上，加上「事前確認、分級回報、逐項確認、統一修改」流程，分析邏輯不變。

## 1. 審查前確認

三項都要先問使用者，一次問完（用 AskUserQuestion，可行時合併為單次提問）。使用者已明確指定的項目不重問。

### 1.1 Base Branch

- 列出候選 branch，供使用者選擇。
- 候選列出 `version/`、`dev` 開頭的 branch 與 `main`；版號最新的 `version/*` 標為建議（依 semver 逐段比較數字，如 `3.10.0` > `3.4.0`）。
- 完全找不到候選 → 請使用者提供，不要猜測。
- 使用者指定其他 branch 時，照其指定。

### 1.2 審查範圍

- 選項：只看 `/frontend` 資料夾、或不限範圍。
- 選「只看 `/frontend`」：其餘檔案一律略過不評論；沒有 `/frontend` 變更就告知無可 review 內容；找不到 `/frontend` 或結構不符預期則詢問。

### 1.3 Effort 等級

- 列出可選等級：`low`、`medium`、`high`、`xhigh`、`max`。
- 使用者沒特別指定 → 採用 `high`，並在回覆開頭註明。

## 2. 執行審查

1. 依 1.1 取得 diff 與變更檔案清單。
2. 依 1.2 過濾範圍；為空則告知並結束。
3. 以 1.3 的 effort 等級，用原生 `/code-review` 邏輯審查。若有多個 agent 各自產出建議，合併去重後統一編號。

## 3. 回報格式

全部使用繁體中文（台灣用語）；程式碼、變數、函式、檔名、指令維持原文。

- 開頭註明：base branch、審查範圍、effort 等級。
- 依嚴重性分類，由高到低：**嚴重**（會壞功能、資料或安全）、**重要**（高機率出問題）、**一般**（可維護性、邊界情況）、**建議**（風格、小優化）。沒有項目的分類不列。
- 每項建議有全域唯一編號（如 `#1`、`#2`），並包含：位置（檔案與行號）、問題說明、影響、建議修法。
- **與使用者操作有關的問題，必須附重現方式**：到哪個畫面的哪個區塊、依序做哪些操作、預期結果與實際結果。純內部邏輯、型別、風格類問題不需要。
- 無法確定問題真的會發生時，如實標註「待確認」，不要寫成確定的 bug。

## 4. 逐項確認，先不改

使用者會針對每項回覆處置，例如「改」、「略過」，或提問如「這是什麼意思？真的存在嗎？」。

- 收到提問 → 重新查證程式碼後解釋，必要時補充重現方式；若查證後發現不成立，直接承認並建議略過。回答提問時**不修改任何檔案**。
- 維護一份處置清單（編號 → 改／略過／待確認），使用者要求時可列出目前進度。
- 使用者沒回覆的項目，視為「略過」。

## 5. 統一修改

- 所有項目都已決定（沒有「待確認」；未回覆的已視為略過）後，才一次修改所有標為「改」的項目。
- 動手修改之前，先把目前所有未 commit 的檔案 stage（`git add -A`），讓使用者之後用 `git diff` 只看到這次的修改。
- 修改只涵蓋標為「改」的項目，不順手改其他地方。
- 修改完成後回報：每個編號對應改了哪些檔案；略過的項目列出編號即可。
