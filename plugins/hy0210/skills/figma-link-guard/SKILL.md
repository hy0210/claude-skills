# figma-link-guard — Figma 連結安全守則

使用者提供 Figma 連結時，依序遵守以下規則，不得跳過任何步驟。

## 規則 1：MCP 優先，失敗就停

使用 Figma MCP 工具（`get_design_context`、`get_metadata` 等）開啟連結。

- 若 MCP 工具呼叫**失敗、回傳錯誤、或無回應**，立即停止。
- 不得改用截圖（`get_screenshot`）或其他方式繞過。
- 告知使用者發生什麼錯誤，等待使用者確認連結正確或提供新連結後，才能繼續。

## 規則 2：回傳資料過大 → 依任務類型決定

若 MCP 工具成功回傳，但資料量異常龐大（例如回傳整個檔案的所有 frame、大量巢狀節點），視為連結可能指向錯誤的範圍。

**先判斷任務是否需要嚴格樣式數值**：

- **需要嚴格樣式**（實作或驗證顏色、間距、字型、尺寸等精確數值）：
  - **不得**繼續分析這份過大的資料，**不得**改用 `get_screenshot` 作為替代方案。
  - 停下來，向使用者說明：「回傳資料量異常龐大，連結可能指向了錯誤的頁面或範圍，請確認連結是否正確。」
  - 等待使用者回覆後才繼續。
- **不需要嚴格樣式**（單純定位元件、探索畫面結構、確認連結是否對應正確頁面等）：
  - 可改用 `get_screenshot` 輔助確認，不必停下來詢問使用者。
  - 若截圖後仍無法判斷連結是否正確（畫面明顯不符或無法辨識），照樣停下來詢問使用者，不得自行猜測。

若不確定任務屬於哪一類，視為**需要嚴格樣式**，依原規則停下來詢問。

## 規則 3：內容與描述不符 → 停下來問

若 MCP 成功回傳，但內容（元件名稱、畫面結構、文字）與使用者的文字描述明顯不符：

- **不得**自行猜測使用者意圖。
- **不得**以「可能是這個」的方式繼續實作。
- 停下來，向使用者說明：「目前連結內容與描述不符，請確認連結是否正確，或補充說明。」
- 等待使用者確認後才繼續。

## 禁止行為總覽

| 情況 | 禁止 | 應做 |
|------|------|------|
| MCP 開啟失敗 | 改用截圖、繼續推測 | 停下來回報錯誤，等待使用者 |
| 回傳資料過大（需嚴格樣式） | 改用截圖、繼續分析 | 停下來詢問連結是否正確 |
| 回傳資料過大（不需嚴格樣式） | 自行猜測、跳過確認 | 可改用 `get_screenshot` 輔助判斷；仍無法判斷時才停下來詢問 |
| 內容與描述不符 | 自行猜測、繼續實作 | 停下來詢問連結是否正確 |
