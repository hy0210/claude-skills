# Sub-Skill: Verify Browser

> 由 `implement-issue` 主 skill 在步驟 6 載入。這是最後一個步驟，完成後整個 implement-issue 流程結束。

## 目的
輸出實作總結，交由使用者手動驗證。若使用者回報問題，才用 agent-browser 比對實際情況與設計稿的差異並修正。

---

## 1. 實作總結

步驟 5 完成後，直接輸出總結，**不主動啟動 agent-browser 驗證**：

```
## 實作總結

### 修改的檔案
| 檔案 | 對應需求 |
|------|----------|
| path/to/file.tsx | 需求項目 1、2 |
| ... | ... |

### 驗證結果
- 測試：✅ 通過 / ❌ 失敗（說明）
- Lint：✅ 通過 / ❌ 失敗（說明）

### 注意事項（如有）
- 發現但未修改的潛在問題：...
```

輸出後等待使用者手動驗證。

---

## 2. 使用者回報問題時：Agent-Browser 追查與修正

僅在使用者回報問題後才執行：

0. **確認登入方式**：開啟頁面前，先檢查是否已有該專案的登入/session 復用方式（例如既有的 session state 檔案、memory 中記錄的復用指令）。有的話直接復用；沒有的話，向使用者詢問此專案的登入方式，不可自行假設帳密或跳過登入
1. 用 agent-browser 開啟實際頁面，重現使用者回報的問題
2. 若問題涉及 UI 樣式，用 Figma MCP 開啟對應節點，比對實際畫面與設計稿的差異（顏色、字型、間距、尺寸等）
3. 若問題涉及行為邏輯，對照 issue 描述與程式碼實作，找出差異點
4. 修正後，用 agent-browser 重新操作確認問題已解決
5. 若懷疑是設計稿或需求本身的問題（而非實作錯誤），停止並詢問使用者，不可自行推測

---

## 完成條件
- 實作總結已輸出
- 若使用者回報問題，已用 agent-browser（必要時搭配 Figma MCP）修正並確認解決

`implement-issue` 流程至此結束。
